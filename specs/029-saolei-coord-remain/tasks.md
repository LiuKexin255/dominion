## Conventions (Constitution — apply to EVERY task)

- **§IV Compile + unit test gate**: every code task MUST end green on the relevant Bazel target(s) — this is part of the task, NOT a separate task. Run `bazel build //...` + the target's `bazel test` after each code change.
- **§V Read-before-code**: each phase declares its 文档清单 below; read ALL listed docs (including external URLs — Read has no transitive loading) before coding in that phase. `AGENTS.md` and the spec are pre-read, not listed.
- **§I Citation**: code comments that reference design decisions cite repo-relative paths (e.g. `specs/029-saolei-coord-remain/contracts/saolei-board-render-contract.md §2`) or full URLs — no bare refs like `FR-002`.
- **Bazel/Gazelle** (AGENTS.md): after editing TS, `bazel run //:go -- fmt <files>` is N/A (Go formatter). No TS formatter is configured; formatting is manual. Run `bazel run //:gazelle` ONLY if a new file/dep is added — this feature adds **no new file under a globbed dir that changes deps** and **no new external dep** (`@dominion/game-saolei-board` is already in `projects/game/agent/BUILD.bazel` deps), so no gazelle run is expected.
- **Format source of truth**: every expected ruler string (tests, goldens) is derived from `specs/029-saolei-coord-remain/contracts/saolei-board-render-contract.md` §1/§2 — re-read it before writing any assertion or golden.

## Phase 3: User Story 2 — `saolei_remain` Tool (Priority: P1)

**Goal**: A fifth, read-only saolei MCP tool `saolei_remain()` that returns the remain grid (number cell → `number − adjacent flags`, raw/negative; `0` and non-numbers → `-`), reusing US1's `renderGridWithRuler` for its ruler (spec FR-006..FR-013).

**Independent Test**: With a saolei profile, a unit test drives `saolei_init` then `saolei_remain()` and asserts the body contains `saolei_remain → computed`, `game status: playing`, `board size …`, a tagged remain grid, and that the fake `OperationBridge` recorded ZERO dispatches for the call; `bazel test //projects/game/agent:lib_test` green.

**Depends on**: US1 (Phase 2) — `renderGridWithRuler` must be exported from `@dominion/game-saolei-board`.

**文档清单** (read ALL before coding):

- **官方文档**: MCP Tools content blocks — https://modelcontextprotocol.io/docs/concepts/tools (the tool returns one text content block; `registerTool` API + neutral status per 023 C15)
- **技术文章**: 无
- **Feature docs (design)**: `specs/029-saolei-coord-remain/contracts/saolei-remain-tool-contract.md` (§1 surface, §2 no-dispatch, §3 computation, §4 body shape, §5 lifecycle, §8 test anchors), `specs/029-saolei-coord-remain/contracts/saolei-board-render-contract.md` §2 (`renderGridWithRuler` signature), `specs/029-saolei-coord-remain/data-model.md` (Entity 2), `specs/029-saolei-coord-remain/research.md` (D3 computation, D4 body/lifecycle, D6 five-tool surface)

- [ ] T005 [US2] (depends on US1 / T002 export) In `projects/game/agent/src/mcp/saolei/saolei-mcp.ts`, register the `saolei_remain` tool (no `inputSchema`, like `saolei_init`). Handler: if `recognized == null` return `rejectionText("no_active_game", null)`; else compute the remain grid cell-by-cell per contract §3 — for `state.grid[y][x]` ∈ the existing `CHORD_NUMBERS` (`"1".."8"`), `remain = parseInt(cell) − count(neighbors(state,x,y) that are "FLAG")` via the existing `neighbors` helper (`saolei-mcp.ts:253`), output `String(remain)` (raw, may be `0`/negative); for every other cell (`"0"`, `INITIAL`, `FLAG`, `HIT_MINE`, `MINE`, `UNKNOWN`) output `"-"`. The handler MUST NOT call `bridge.dispatch` and MUST NOT mutate `recognized`. No BUILD change (`@dominion/game-saolei-board` already in `projects/game/agent/BUILD.bazel` deps). Run `bazel test //projects/game/agent:lib_test`.
