**Created**: 2026-09-03

**Status**: Draft

## Motivation

`specs/051-agent-v2-dsh-migration/` 交付了"web 驱动 agent 玩扫雷"的端到端闭环，但用户在实际部署的正式环境人工测试（2026-09-03）发现 8 个缺陷/需求：4 个主要缺陷使核心体验不可用（消息挤成一团、无 markdown、桌面游戏不被真实驱动、已见内容刷新后丢失），1 个新增能力（终止按钮），3 个次要问题（preset 编辑中间态、菜单视觉缺失、模型目录不全）。本 feature 修复全部缺陷并交付终止能力，使 051 的验收价值（US1 网页驱动一局完整扫雷）真实成立。

缺陷定位（调研结论，作为修复背景；正式环境核实：生产部署无任何模拟组件——LLM 端点默认为真实智谱端点 `projects/game/agent_v2/src/dsh.ts` 的 `GLM_DEFAULT_BASE_URL`，部署清单 `projects/game/deploy.yaml` 未注入覆盖变量，模拟执行器仅存在于测试部署 `projects/game/testplan/deploy_agent_v2.yaml`）：

- **消息挤在一个气泡**：对话进行中，前端将整个回合合并为单条 agent 消息渲染（`projects/game/web/frontend/src/store/chat.ts` 的 turnEnd 归约）；而服务端历史按模型输出步骤（step）逐条记录（`common/js/dsh-plugins/saolei-loop/src/driver.ts` 每 step 追加 `assistant/message`），刷新回填后呈现为多条消息——同一回合**流式与回填的分段不一致**，且流式期间所有内容（思考、工具调用、正文）挤在一个视觉容器里。
- **markdown 未渲染**：正文以纯文本组件呈现（组件库提供的 markdown 组件未被使用），模型输出的标题/列表/代码块/表格等以原始符号显示。
- **desktop 未执行却有游戏状态**：代码链路核查确认游戏状态必须来自操作回传截图的识别（`common/js/dsh-plugins/saolei-loop/src/game/runtime.ts`），生产部署无模拟路径、dispatch 会话标识两端一致——为真实链路缺陷，根因（如会话错配、连接未达、LLM 输出虚构状态）以实际环境排查为准。用户困惑的直接根源之一是 **web 上完全没有该会话桌面连接状态的可见性**。
- **已见内容刷新后丢失**：服务端仅在 LLM 流正常结束时固化该步骤内容（`driver.ts` step 循环：流失败路径不追加 `assistant/message`）；前端对失败回合丢弃已流出的全部内容（`store/chat.ts` 的 ERROR 归约）。双重丢失导致"看到过的超大气泡，关闭重开后只剩自己输入的消息"。
- **模型目录只有 glm-5.2**：组合清单的模型目录仅配置单条目（`projects/game/agent_v2/cordis.yml` llm-glm `models`：`GLM_MODEL || 'glm-5.2'`），而 GLM Coding Plan 当前支持的模型为 GLM-5.3、GLM-5.3-Flash（历史模型名会被官方端点自动切换，见 [GLM Coding Plan 套餐概览](https://docs.bigmodel.cn/cn/coding-plan/overview)）——且当前默认名 glm-5.2 实际已被静默切换，物化表单无从选择其他模型。
- **preset 编辑时列表残留**：编辑表单与列表同页呈现，列表各条目操作按钮全部禁用，呈现"看得见但点不了"的中间态（`projects/game/web/frontend/src/components/PresetsView.tsx`）。
- **`···` 菜单不成形**：菜单卡片所需的背景/边框/阴影样式变量未在 web 主题中定义（`projects/game/web/frontend/src/theme.css`），弹出菜单渲染为透明无边框的浮层，只剩一个红色"删除"文字按钮——看起来像"session 条目下方展开的红色按钮"而非弹窗菜单。
- **无终止能力（新增需求）**：agent 回合运行中（尤其失控场景）用户没有任何停止手段；服务端已有回合收集中止的内部缝（`projects/game/agent_v2/src/history.ts` TurnCollector abort）但对话面无暴露入口。

## Clarifications

### Session 2026-09-03

- Q: agent 一轮对话输出的分段粒度与终态形态（每 step 一气泡平铺 / 每内容块一气泡 / 回合单容器内部分隔）？ → A: 对齐 dsh 官方 webUI 的 **Turn Process Folding** 模型（`@deepseek-ai/dsh-client-ui-chat` README "Turn Process Folding" 与 `chat-nodes.d.ts`，包 npm 主页 https://www.npmjs.com/package/@deepseek-ai/dsh-client-ui-chat ，源仓库 https://github.com/deepseek-ai/deepseek-harness ）：流式期间逐 step 分段依次独立呈现（步骤内思考折叠块/工具卡片/正文分类分列）；回合完成后最终答案（最后一个含正文且无工具调用的步骤）独立呈现，此前的步骤默认折叠为可展开的"思考过程"摘要区（含规模提示）；无最终答案的回合（失败/终止/纯工具调用结束）保持全部过程内容可见；回填默认呈现折叠态，手动展开在页面会话内保持。
- Q: 用户终止当前回合时，会话中已排队的消息应如何处置？ → A: **落地为用户历史消息**：agent 停止，排队消息自队列移除并固化进会话历史（作为用户消息，回填可见），不触发新的 agent 回合；此后用户发送新消息时，已落地消息作为普通的历史用户消息参与上下文（不单独触发处理）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 桌面游戏被真实驱动，且连接状态可见 (Priority: P1) 🎯 MVP

用户在 web 对话页向已物化 agent 的 session 发送"开始一局扫雷"；用户已确认该 session 的桌面连接状态（对话页可见"桌面已连接/未连接"指示）；agent 调用扫雷工具后，**desktop 真实收到并执行操作指令（新局按键、格子点击），桌面扫雷游戏真实开始并进行**；工具结果中的棋盘与桌面实际画面一致。若桌面未连接/连接的是其他 session，用户能在对话发起前就从状态指示发现，工具结果也以明确错误呈现（而非出现来路不明的游戏状态）。

**Why this priority**: 051 的核心验收价值（US1 网页驱动完整一局游戏）当前不成立——用户在正式环境看到工具调用与游戏状态但桌面毫无动静，无法判断真假。这是"能不能用"的问题，优先于"呈现好不好看"。

**Independent Test**: 真实环境端到端：desktop 连接正确 session 并绑定窗口 → web 发送游戏指令 → 断言 desktop 日志/界面可见操作执行、桌面扫雷游戏真实开始、web 工具结果棋盘与桌面一致；断开 desktop 后重复 → 断言状态指示为未连接、工具结果为明确错误、无游戏状态出现。

**Acceptance Scenarios**:

1. **Given** desktop 已连接 session S 并绑定扫雷窗口，**When** 用户在 web 对话页向 S 发送"开始一局扫雷"，**Then** desktop 收到并执行新局指令，桌面扫雷游戏真实开始，web 工具结果呈现的棋盘与桌面实际状态一致。
2. **Given** 某会话的桌面连接状态，**When** 用户查看对话页，**Then** 该会话的桌面连接状态（已连接/未连接）清晰可见（进入对话页与连接状态变化时均准确反映）。
3. **Given** desktop 未连接或连接的是其他 session，**When** agent 调用需要桌面执行的工具，**Then** 工具以明确的可读错误结果呈现（如"桌面未连接"），不出现任何虚构的游戏状态，回合不崩溃。
4. **Given** 游戏进行中的连续操作（含批量），**When** agent 依次调用操作工具，**Then** 每次操作都在 desktop 真实执行，棋盘随真实执行结果刷新。
5. **Given** desktop 中途断开，**When** 游戏进行中，**Then** 在途操作以明确错误结果返回，连接状态指示变为未连接，重连后游戏可继续。

### User Story 2 - agent 输出按步骤分段呈现，完成后收进思考过程区 (Priority: P1)

agent 一轮对话包含多个输出步骤（如：思考+调用工具 → 收到结果后继续思考 → 最终正文），呈现方式对齐 dsh 官方 webUI（Turn Process Folding 模型）：**流式进行中**，每个步骤的分段依次独立呈现——思考折叠块、工具卡片、正文分类分列，互不挤在同一个视觉容器里；**回合完成后**，最终答案（最后一个含正文且无工具调用的步骤）独立呈现，此前的步骤（思考、工具调用、中间正文）默认折叠为**可展开的"思考过程"摘要区**（含规模提示，如步骤/工具计数）。刷新页面或重新进入后，历史回填的呈现与流式结束时的形态**一致**（默认折叠态，手动展开在页面会话内保持）。

**Why this priority**: 用户报告的最主要问题之一：当前流式回合把思考、工具调用、正文全部挤在一个"思考过程"大气泡里，多步推理的游戏过程完全不可读；且刷新前后分段不一致加剧困惑。

**Independent Test**: 驱动一轮包含工具调用的多步对话（测试可用确定性模拟模型），断言：流式期间多个分段依次独立呈现、回合完成后最终答案独立且此前步骤折叠（可展开）、刷新回填后形态与流式结束时一致。

**Acceptance Scenarios**:

1. **Given** 一轮含工具调用的多步对话正在进行，**When** agent 逐步输出（思考/工具调用/正文），**Then** 对话页按步骤分段依次独立呈现，而非单一容器内的一个"思考过程"大块。
2. **Given** 步骤内同时含思考与工具调用，**When** 该步骤呈现，**Then** 思考内容为独立的思考折叠块、工具调用为独立的工具卡片，二者视觉分离、可独立展开收起。
3. **Given** 一轮对话完成（最终步骤含正文），**When** 回合结束，**Then** 最终答案独立呈现，此前的步骤（思考、工具调用、中间正文）默认折叠为"思考过程"摘要区（含规模提示），点击可展开查看全过程。
4. **Given** 一轮对话完成，**When** 用户刷新页面或切换回该会话（历史回填），**Then** 呈现形态与流式结束时一致（默认折叠态，最终答案独立可见），用户手动展开的操作在页面会话内保持。
5. **Given** 一轮对话以无最终答案的方式结束（失败/被终止/以纯工具调用结束），**When** 回合结束或回填，**Then** 全部过程内容保持可见（不折叠隐藏过程证据）。
6. **Given** 用户消息，**When** 呈现，**Then** 用户消息与 agent 消息的分段规则不因本变更改变（用户消息仍为独立气泡）。

### User Story 3 - 气泡内容以 markdown 正常渲染 (Priority: P1)

agent 正文输出中的 markdown 格式（标题、列表、粗体/斜体、行内代码、代码块、表格、链接）在气泡中**渲染为格式化内容**而非原始符号；流式输出过程中 markdown 渲染稳定（不因内容增量而闪烁错乱）；工具结果中的文本棋盘保持等宽对齐呈现（预格式化，不被 markdown 误排）。

**Why this priority**: 用户报告的最主要问题之二：当前正文纯文本呈现，模型的任何 markdown 输出都是原始符号，可读性差；游戏叙事（步骤列表、坐标说明）尤其依赖列表与代码格式。

**Independent Test**: 驱动一轮包含 markdown 元素（列表/代码块/表格/粗体）的回复，断言：渲染后为格式化呈现（非原始符号）、流式期间与完成后渲染稳定、工具结果中的棋盘文本等宽对齐。

**Acceptance Scenarios**:

1. **Given** agent 正文包含 markdown 元素（标题/列表/粗体/行内代码/代码块/表格/链接），**When** 气泡呈现，**Then** 渲染为对应格式化内容，无原始 markdown 符号裸露。
2. **Given** 流式输出正在进行且内容持续增量，**When** 用户查看气泡，**Then** markdown 渲染随内容增长平滑更新，无结构性闪烁或错乱。
3. **Given** 工具结果包含文本棋盘（含坐标标尺的预格式化文本），**When** 呈现，**Then** 棋盘以等宽字体预格式化对齐显示，行列不因 markdown 渲染而错位。
4. **Given** 历史回填的消息，**When** 呈现，**Then** markdown 渲染与流式结束时一致。

---

### User Story 4 - 已呈现的内容刷新后不丢失（失败回合内容保留） (Priority: P1)

用户在对话页**已经看到过的 agent 内容**（流式呈现过的思考、工具调用、正文），无论回合最终以何种状态结束（成功/失败/被终止），在刷新页面或重新进入会话后**都能从历史回填中再次看到**；失败提示独立呈现，不吞掉已产出的内容。用户不再遇到"看过的大气泡关闭页面后消失、只剩自己输入的消息"。

**Why this priority**: 用户报告的最主要问题之四：内容"看过即焚"直接破坏对话产品的信任基础（用户无法回顾 agent 做过什么），且与问题 3 复合——失败回合的内容恰恰是排查链路问题最需要的证据。

**Independent Test**: 驱动一轮中途失败的对话（测试可注入失败），断言：流式期间已呈现的内容在刷新回填后仍然可见（与流式结束时一致）、失败提示独立呈现；正常成功回合的回填行为不回归。

**Acceptance Scenarios**:

1. **Given** 一轮对话的模型流式输出已完成部分内容后回合以失败结束，**When** 用户刷新页面，**Then** 已流式呈现过的内容（含思考、工具调用及其已得结果）经回填再次可见，失败提示独立呈现。
2. **Given** 一轮对话成功结束，**When** 用户刷新页面，**Then** 全部内容回填可见（既有行为零回归）。
3. **Given** 回合被用户终止（US5），**When** 用户刷新页面，**Then** 终止前已产出的内容回填可见。
4. **Given** 回合失败当刻，**When** 用户不刷新继续会话，**Then** 已呈现的分段内容不被原地清空，失败提示独立呈现，输入可重试。

### User Story 5 - 对话页可优雅终止运行中的 agent (Priority: P2) 

agent 回合运行期间，对话页呈现**终止按钮**；用户点击后当前回合**尽快停止**（模型流式与在途工具执行传播取消，不再产生新动作），终止前**已产出的内容保留**（分段呈现且刷新后回填一致），回合以明确的"已终止"终态呈现（区别于失败），会话立即恢复可输入状态，排队中的消息语义行为可预期。

**Why this priority**: 新增需求（用户明确要求）：当前回合一旦发起便无法停止——在 agent 失控（如反复无效工具调用）或用户改变意图时只能干等；终止按钮是用户对会话的控制权兜底。定位 P2：新增能力而非缺陷修复，不阻塞 P1 缺陷修复的独立交付。

**Independent Test**: 驱动一轮长回合（测试用可控延迟的模型/工具），运行中点击终止：断言回合在短时间内停止、不再有新的流式内容与工具执行、已产出内容保留且刷新后可见、终态标识为终止（非失败）、输入框立即可用、可立即发起新一轮对话。

**Acceptance Scenarios**:

1. **Given** 一轮回合正在运行（流式输出或工具执行中），**When** 用户查看对话页，**Then** 终止按钮可见且可点击（空闲时不呈现或不可用）。
2. **Given** 回合运行中，**When** 用户点击终止，**Then** 当前回合尽快停止（≤5 秒内收到终止终态，SC-004）：模型流式与在途工具执行被取消，不再产生新的输出块或工具调用，桌面不再收到新的操作下发。
3. **Given** 回合被终止，**When** 终止完成，**Then** 终止前已产出的内容保留呈现（分段不丢），回合以"已终止"终态标识（区别于失败），刷新后回填一致。
4. **Given** 回合被终止，**When** 用户查看输入区，**Then** 输入立即可用，可立即发起新一轮对话（会话不锁定、无需等待）。
5. **Given** 终止时仍有排队消息，**When** 终止完成，**Then** 排队消息落地为用户历史消息（队列清空、不触发 agent 回合、回填可见）；此后用户发送新消息时，已落地消息作为普通的历史用户消息参与上下文。
6. **Given** 非运行状态（空闲），**When** 用户查看对话页，**Then** 终止操作不可触发（无副作用、不产生错误终态）。

### User Story 6 - 物化模型目录覆盖 GLM Coding Plan 全部模型 (Priority: P2)

用户在 agent 物化面板的模型下拉中可以看到**GLM Coding Plan 当前支持的全部模型**（如 GLM-5.3、GLM-5.3-Flash），选择任一模型物化后 agent 实际使用该模型；目录不呈现会被官方端点静默替换的历史模型别名；默认模型为目录中的有效模型；目录与物化校验同源（051 既有语义）。

**Why this priority**: 次要问题之三：当前目录仅单一模型且实为会被自动切换的历史别名（glm-5.2 → glm-5.3），用户无从选择更快/更省的模型变体；修复属配置完善，独立可交付。

**Independent Test**: 查询模型目录断言覆盖官方文档所列当前支持模型；物化选定非默认模型后对话断言实际生效（模型标识可见）；未知模型 id 物化仍被拒绝（同源校验零回归）。

**Acceptance Scenarios**:

1. **Given** GLM Coding Plan 当前支持的模型集合（以[官方套餐文档](https://docs.bigmodel.cn/cn/coding-plan/overview)为准），**When** 用户打开物化面板模型下拉，**Then** 全部当前支持模型可选，无缺失。
2. **Given** 模型下拉，**When** 用户选择某非默认模型物化，**Then** 该 agent 实际使用所选模型（对话行为/标识可佐证），物化配置查询反映所选。
3. **Given** 模型下拉，**When** 呈现默认项，**Then** 默认模型为目录中实际有效的模型（非会被静默替换的别名）。
4. **Given** 物化请求携带未知模型 id，**When** 提交，**Then** 被明确拒绝（051 FR-006 fail-fast 语义零回归）。

### User Story 7 - preset 编辑为独占视图 (Priority: P2)

用户在 preset 管理页点击"新建"或某条目的"编辑"后，**切换为独占的编辑视图**（编辑表单不再与列表同页叠放）；列表（含各条目的编辑/删除按钮）在编辑期间**不呈现**；保存或取消后返回列表，列表反映保存结果。编辑已有 preset 时名称只读、提示词可改（051 既有语义不变）。

**Why this priority**: 次要问题之一：当前编辑表单下方仍渲染列表且所有条目按钮禁用，"看得见但点不了"的中间态违反直觉；独占编辑视图是标准 master-detail 处理。

**Independent Test**: 组件级验证：进入新建/编辑 → 断言列表不呈现、表单字段正确（新建名称可编辑/编辑名称只读）→ 保存/取消 → 断言返回列表且状态正确。

**Acceptance Scenarios**:

1. **Given** preset 管理页，**When** 用户点击"新建"，**Then** 切换为独占编辑视图（列表不呈现），名称可输入、提示词可编辑。
2. **Given** preset 管理页，**When** 用户点击某条目"编辑"，**Then** 切换为独占编辑视图（列表不呈现），名称只读、提示词可编辑。
3. **Given** 编辑视图中，**When** 用户保存成功，**Then** 返回列表且列表反映最新内容与更新时间。
4. **Given** 编辑视图中，**When** 用户取消，**Then** 返回列表且内容不变。
5. **Given** 编辑视图中，**When** 保存失败（如网络错误），**Then** 错误清晰呈现且停留在编辑视图（已输入内容不丢失）。

### User Story 8 - `···` 弹出视觉完整的菜单 (Priority: P2)

用户点击 session 条目右侧的 `···` 按钮后，弹出**视觉完整的浮层菜单**：有可见的菜单卡片容器（背景、边框、阴影），呈现于按钮旁的浮层中，菜单内含"删除"项；点击"删除"进入确认步（菜单内确认/取消），确认后执行删除。菜单不被列表滚动区域裁剪，点击菜单外或按 Esc 关闭菜单。

**Why this priority**: 次要问题之二：菜单卡片样式缺失（背景/边框/阴影样式变量未定义）导致弹出物是透明浮层里一个红色"删除"文字——用户感知为"条目下方展开的红色按钮"而非弹窗菜单。顺带需系统性核查已用组件的样式变量完整性，防止同类缺陷。

**Independent Test**: 组件级验证：点击 `···` → 断言浮层菜单以完整卡片视觉呈现（有背景/边框/阴影容器、正确定位）且含"删除"项；确认流可用；菜单外点击/Esc 关闭；列表滚动时菜单完整可见不被裁剪。

**Acceptance Scenarios**:

1. **Given** session 列表，**When** 用户点击某条目 `···` 按钮，**Then** 弹出浮层菜单，菜单有完整的卡片容器视觉（背景/边框/阴影），定位于按钮旁而非条目下方的裸按钮形态。
2. **Given** 菜单已打开，**When** 用户点击"删除"，**Then** 菜单进入确认步（确认删除/取消），确认后该 session 按既有删除编排移除。
3. **Given** 菜单已打开，**When** 用户点击菜单外任意位置或按 Esc，**Then** 菜单关闭且不触发删除。
4. **Given** 列表较长且目标条目位于列表底部（滚动容器内），**When** 打开其菜单，**Then** 菜单完整可见、不被滚动容器裁剪。
5. **Given** web 使用的其余基础组件（按钮/输入框/状态点等既有呈现），**When** 本 feature 交付后渲染，**Then** 无因样式变量缺失导致的视觉缺失（系统性核查补齐）。

### Edge Cases

- **回放分段与流式一致性的边界**：回合中途失败（错误/中止/终止）时不产生"半段气泡"——失败/终止前的已完成步骤按步骤分段保留（与服务端历史一致），失败/终止提示独立呈现；不因分段改造引入丢块或重复块。
- **历史中无结果的工具块**：回合异常结束（如在途工具未回结果）后回填历史时，该工具块不得呈现为"永久运行中"（应呈现为中断/失败终态）。
- **空文本步骤**：模型输出中的空正文步骤不产生空气泡（既有"空 text 块跳过"语义延续）。
- **markdown 渲染安全**：渲染模型输出时不产生注入风险（内容按 markdown 数据渲染而非可执行内容）；不完整的 markdown 片段（流式中途）不导致渲染崩溃。
- **终止时在途工具/桌面操作**：终止传播到在途工具执行——已下发的桌面操作按既有中止语义结算（明确结果、不悬挂等待超时）；终止后桌面不再收到新操作。
- **终止与其他操作并发**：终止与重新物化（Update）、session 删除并发时行为遵循既有终态语义（不产生半清理/半终止状态）。
- **桌面连接状态判定边界**：状态指示以 agent 侧连接事实为准（非 desktop 本地自认）；同一 session 重复连接按"新连接接管"语义（051 既有），状态指示不因接管瞬时抖动产生误导（最终一致即可）。
- **模型目录与官方切换策略**：目录仅呈现实际有效的模型（官方对历史别名做自动切换，呈现别名会掩盖实际模型）；模型升级换代（官方上下架）时目录以配置为单一来源、更新不需改动代码逻辑。
- **菜单与两步确认的并发**：删除进行中该条目菜单项禁用（既有语义延续）；一条菜单打开时打开另一条的菜单，旧菜单关闭。
- **preset 编辑视图与删除竞态**：051 既有语义（正在编辑的条目被删除时自动关闭表单）在独占视图形态下延续——返回列表且不残留已删除条目。

## Requirements *(mandatory)*

### Functional Requirements

#### 游戏链路真实性与可观测性（用户主要问题 3）

- **FR-001**: 真实环境下（真实 desktop + 真实模型），web 对话页发起游戏指令后，agent 的扫雷工具操作 MUST 真实下发到连接该 session 的 desktop 并执行：desktop 侧可见操作执行记录，桌面扫雷游戏真实开始与推进，web 工具结果呈现的棋盘 MUST 与桌面实际状态一致。实现方 MUST 排查定位当前"工具显示调用内容与游戏状态、桌面却无任何执行"的链路断点并修复（排查以正式环境的实际执行证据为准，不得凭推测改代码）。
- **FR-002**: web 对话页 MUST 呈现该 session 的桌面连接状态（已连接/未连接），状态 MUST 反映 agent 侧的连接事实（连接建立、断开、接管时更新）；状态不可用或获取失败时 MUST 有明确的降级呈现（如"状态未知"），不得静默显示为已连接。
- **FR-003**: 桌面不可达（未连接/连接其他 session/中途断开）时，需要桌面执行的工具 MUST 以明确可读的错误结果呈现（对用户与模型均可见），MUST NOT 出现任何非真实执行产生的游戏状态；回合与进程存活（051 US1 场景 4/5 语义保持）。

#### 对话消息分段呈现（用户主要问题 1）

- **FR-004**: agent 回合的多步输出 MUST 按步骤（step，服务端历史的消息粒度）分段呈现：流式进行中即按步骤分段（步骤完成即成段，无需等待回合结束），各分段依次独立呈现；历史回填呈现相同分段。
- **FR-005**: 回合完成后的终态 MUST 按官方 Turn Process Folding 模型收束（见 Clarifications 2026-09-03）：最终答案（最后一个含正文且无工具调用的步骤）独立呈现，此前的步骤（思考、工具调用、中间正文）默认折叠为可展开的"思考过程"摘要区（含规模提示，如步骤/工具计数）；无最终答案的回合（失败/被终止/以纯工具调用结束）MUST 保持全部过程内容可见；回填默认呈现折叠态，手动展开在页面会话内保持。
- **FR-006**: 各内容类型 MUST 保持独立视觉单元：思考内容为独立折叠块（可展开收起）、工具调用为独立工具卡片、正文为独立气泡；一个步骤内同时含多种内容时（如思考+工具调用）MUST 分类分列呈现，MUST NOT 混排为单一文本流。
- **FR-007**: 分段改造 MUST 保持既有对话行为零回归：用户消息呈现、排队指示、错误提示、工具结果按 tool_id 关联终态化、未知事件前向兼容等 049/051 既定语义不变。

#### markdown 渲染（用户主要问题 2）

- **FR-008**: agent 正文气泡 MUST 以 markdown 渲染（至少支持：标题、有序/无序列表、粗体/斜体、行内代码、代码块、表格、链接），MUST NOT 裸露原始 markdown 符号；历史回填与流式呈现的渲染结果一致。
- **FR-009**: 流式增量内容下的 markdown 渲染 MUST 稳定更新（无结构性闪烁/错乱/崩溃）；内容按数据渲染（MUST NOT 存在注入执行面）。
- **FR-010**: 思考折叠块的展开内容 MUST 同样以 markdown 渲染（与正文一致的能力）。
- **FR-011**: 工具结果中的文本棋盘 MUST 以等宽预格式化呈现（保持坐标标尺对齐），MUST NOT 因 markdown 渲染导致行列错位。

#### 失败回合内容保留与回填一致（用户主要问题 4）

- **FR-012**: 服务端历史固化 MUST 覆盖所有回合终态：回合无论以成功、失败、中止还是终止结束，**已产出的步骤内容**（流式已完成的块，含中断前缀）MUST 固化进会话历史（回填可见），MUST NOT 因回合最终失败而整回合丢弃。
- **FR-013**: 前端在回合失败/终止时 MUST 保留已流式呈现的分段内容（不清空、不原地消失），失败/终止提示 MUST 独立呈现（不吞掉内容）；刷新后回填所见与流式结束时所呈现的一致。
- **FR-014**: 既有成功回合的回填行为 MUST 零回归（成功回合回填内容与分段不变）。

#### 对话页终止按钮（用户新增需求）

- **FR-015**: 对话页 MUST 在回合运行期间提供终止入口：运行中可点击，空闲时不可触发（无副作用）；触发后当前回合 MUST 尽快停止——模型流式与在途工具执行传播取消，不再产生新的输出块、工具调用或桌面操作下发。
- **FR-016**: 终止 MUST 为优雅语义：终止前已产出的内容保留（分段呈现且满足 FR-012/013 的回填一致性）；回合以明确的"已终止"终态呈现（区别于失败）；终止后会话立即恢复可输入、可发起新回合；在途工具按既有中止语义结算（明确结果、不悬挂）。
- **FR-017**: 终止时的排队消息 MUST 落地为用户历史消息（2026-09-03 用户裁定）：排队消息自队列移除并固化进会话历史（作为用户消息，回填可见），MUST NOT 触发新的 agent 回合；此后用户发送新消息时，已落地消息 MUST 作为普通的历史用户消息参与上下文（不单独触发处理）。行为 MUST 有对应测试断言。

#### 模型目录（用户次要问题 3）

- **FR-018**: 物化模型目录 MUST 覆盖 GLM Coding Plan 当前支持的全部模型（以[官方套餐文档](https://docs.bigmodel.cn/cn/coding-plan/overview)为准，当前为 GLM-5.3 与 GLM-5.3-Flash）；目录 MUST 仅呈现实际有效的模型（不呈现会被官方端点静默替换的历史别名）；默认模型 MUST 为目录中的有效模型；目录与物化校验同源、未知模型 id 拒绝的既有语义零回归（051 FR-006）。

#### preset 编辑独占视图（用户次要问题 1）

- **FR-019**: preset 新建/编辑 MUST 为独占编辑视图：编辑期间列表不呈现（不存在"可见但禁用"的列表）；保存成功或取消后返回列表；保存失败时停留在编辑视图且已输入内容不丢失、错误清晰呈现。
- **FR-020**: 编辑语义延续 051：编辑时名称只读（创建后不可改）、提示词为编辑主体；新建时名称可输入。空态引导（无 preset 时）语义不变。

#### `···` 菜单视觉完整（用户次要问题 2）

- **FR-021**: `···` 菜单 MUST 以完整的浮层菜单卡片视觉呈现（可见背景、边框、阴影的容器，浮层定位于触发按钮旁），MUST NOT 呈现为无容器的裸按钮/裸文字形态。
- **FR-022**: web 主题 MUST 补齐所使用的全部基础组件所需的样式变量：交付后已使用的组件（按钮、输入、菜单、状态点、折叠行、工具卡片等）无因样式变量缺失导致的视觉缺失（系统性核查，修复同类隐患而非仅菜单一处）。
- **FR-023**: 菜单交互语义保持 051 FR-003 既定：不依赖选中态、含删除项与确认步、删除进行中禁用、菜单外点击/Esc 关闭、菜单不被列表滚动容器裁剪。

#### 范围与验收

- **FR-024**: 修复 MUST 附带相应测试：消息分段与回填一致性（含折叠终态、失败/终止回合内容保留）、markdown 渲染（含流式与棋盘预格式化）、终止按钮（终态/保留/可继续对话/排队语义）、模型目录（覆盖度/同源校验/默认值）、preset 独占编辑视图、菜单视觉与交互均为组件级或模块级测试；游戏链路修复以真实环境端到端验证记录（执行证据）验收。既有测试（049/051 组件与 store 用例）零回归。

### Key Entities

- **Step 分段（步骤消息）**: agent 回合内按模型输出步骤划分的呈现单元；与服务端历史消息一一对应；内含分类内容（思考折叠块/工具卡片/正文）；回合完成后非最终答案的步骤收进可展开的"思考过程"摘要区（Turn Process Folding 模型）。
- **回合终态（Turn Outcome）**: 回合结束状态的用户可见分类：成功（含用量）、失败（含可读错误）、已终止（用户主动停止）——终止与失败 MUST 可区分。
- **桌面连接状态（Desktop Connection Status）**: session 级的桌面连接事实视图（已连接/未连接/未知），来源为 agent 侧桥接连接事实，呈现于 web 对话页。
- **模型目录（Model Catalog）**: 物化时可选模型的事实清单；单一配置来源；与物化校验同源；覆盖 Coding Plan 当前支持模型。
- **Preset 编辑视图（Preset Editor View）**: preset 管理页的独占编辑形态（新建/编辑共用），与列表视图互斥切换。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 真实环境端到端验收通过：desktop 连接正确 session 后，web 发起游戏指令至一局终局（won/lost）全程，desktop 侧操作执行记录完整、桌面游戏真实进行、web 棋盘与桌面一致；存在可复查的执行证据（执行记录/截图）。
- **SC-002**: 对话呈现缺陷清零：多步回合按步骤分段呈现（流式依次独立成段；完成后最终答案独立、此前步骤折叠为可展开的思考过程区；流式与回填形态一致，经组件级测试断言）；markdown 元素（标题/列表/代码块/表格/粗体/行内代码/链接）全部正确渲染，无原始符号裸露；工具棋盘等宽对齐。
- **SC-003**: 内容不再"看过即焚"：失败/终止回合的已呈现内容在刷新回填后仍可见（经注入失败的组件级测试断言），成功回合回填行为零回归。
- **SC-004**: 终止能力可用：运行中点击终止后回合在 ≤5 秒内停止（组件/模块测试断言点击后 5 秒内收到终止终态；无新输出/新工具执行/新桌面操作），已产出内容保留、终态为终止（非失败）、立即可继续对话（组件级与模块级测试断言，含排队消息语义）。
- **SC-005**: 桌面连接状态在对话页始终可见且准确（连接/断开/接管后 10 秒内反映真实状态；不可达时明确降级呈现）。
